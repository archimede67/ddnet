# Comparing open maps in the editor

Open two maps, including two copies of the same file if you want to inspect scratch edits. Right-click the second map's tab and choose **Compare with active map**. The active map is **Before**; the clicked map is **After**. **Tools > Compare maps** and the **Compare maps** quick action open a selector for both sides. A map cannot be compared with its own tab.

Comparison reads current in-memory content, including unsaved edits. Each pane has a one-line **Before / After** heading with the map name and an unsaved marker (**\***). Hover a heading for source details in the status bar; keep hovering to see the full name, saved path and saved or unsaved state in a wrapping tooltip. **Swap** selects or opens the reversed source pair; an unchanged existing result is reused. Comparison does not save either map. Existing background autosaves continue normally.

## Controls and interpretation

- Comparisons open as persistent **Before / After** tabs alongside maps. Filenames may repeat; comparisons use the identities of the open source documents. Opening an existing ordered pair selects its tab. **Swap** selects or opens the reversed pair, with its own inspection state.
- **Back / Escape** returns to editing and keeps the comparison open. Click a tab or use **Ctrl+Tab / Ctrl+Shift+Tab** to switch documents. Release held keys and mouse buttons before the destination receives editing input; in-progress source gestures are recorded for undo.
- Close a comparison with its **X**, middle-click, or **Ctrl+F4**. **Tools > Reopen comparison** and **Ctrl+Shift+F4** restore the most recently closed comparison without selecting sources again. History keeps up to ten lightweight records for this session, including inspection preferences; closing releases snapshots and rendering buffers. Actual source disposal closes only its dependent comparisons and removes their history. Cancelling a source-close dialog preserves them.
- Edits, undo/redo, settings, envelopes, and asset changes mark affected tabs pending (**\***). Returning to a pending comparison automatically captures the latest contents and displays an updating state. Hidden comparisons do no capture or computation per edit. Unchanged tab switches reuse the previous result, and saving alone does not refresh it. Camera, options, scroll positions, and surviving object selections/visibility are retained. Deleted objects clear their selection; indexed object details are cleared when they cannot be identified safely.
- **By layer / By group** changes how the same result is organized. Changes includes map metadata, images and sounds; envelopes and ordered server settings have dedicated sections. Group properties remain inspectable in layer mode.
- The navigator gives change counts. Select a row to inspect its layers or resource. Select a detail below the canvases to read exact Before/After fields. Tile coordinates and object indices are zero-based. Fixed-point coordinates and envelope values explicitly state their units.
- Four icons above the sidebar select sections: the list icon opens **Changes**, the stacked layers icon opens **Layers**, the line chart opens **Envelopes**, and the terminal opens **Server settings**. Hover an icon for its section name and purpose; the selected icon is highlighted. **Changes** lists map, image, sound and layer differences; **Layers** shows the full group/layer hierarchy, including unchanged content and empty groups; **Envelopes** lists every envelope; **Server settings** opens ordered commands. Envelope and settings entries remain accessible with Context off, including equal resources. Empty sections explain that neither map contains the resource. Drag the sidebar divider to resize all four sections together; the same width is used by every map and comparison tab. Click a name to inspect it and double-click a group name to fold or expand its layers. The compact 12-unit rows, left-hand eyes, gameplay styling, indentation and numbered groups follow the normal editor tree. Green names with **+**, red names with **-**, amber names with **~**, and neutral names with **=** badges indicate added, removed, changed and unchanged content; hover the name for the full status. A group's changed status includes its children's differences; **[?]** still indicates uncertain matching.
- In **Layers**, use the eye buttons to show or hide a layer or group in both panes. A hidden group preserves its children's individual choices; show the group before changing those choices. These controls affect comparison rendering only and never modify either map's editor visibility or saved content. Right-click an eye to solo that group or layer among its peers; right-click again to restore all peers, matching the normal editor gesture. **Show all** restores everything. Hidden items remain in counts and Prev/Next navigation; a notice identifies a hidden focus. Visibility belongs to each comparison tab and survives refresh and the Reopen command. Newly created reversed pairs start with all layers visible.
- After clicking the Layers tree, **Up/Down**, **Page Up/Down**, and **End** navigate its rows; **Left/Right** select a parent or fold/expand a group. **Home** remains Fit. Click the inspector to navigate its details instead. An unchanged selection with context off explains how to reveal its content.
- **Prev / Next**, or **P / N**, move through individual differences across entries in the current section, skipping unchanged items and matching-only notices. Clicking an individual detail, clicking it again after panning, or changing it with the inspector keyboard controls focuses the same location in both panes. In group mode, a child detail focuses its own layer. Each Prev/Next step focuses the changed tile, object, property or structural entry; navigation wraps at either end. **Fit / Home** fits the selected tile, object, layer, or group. Drag either canvas with the left or middle mouse button to pan both; use the wheel over a canvas to zoom both.
- Zoom-out is limited to a useful inspection scale, matching the normal editor's maximum. If a layer or group is too large to fit at that scale, Fit centers on a changed tile or occupied area. Pan or use Prev/Next to inspect the rest; exact differences remain available throughout the map.
- The **Context** button cycles through **off**, **layer/group**, and **map**. Off shows changed content in the selection; layer/group also shows its unchanged content. Map shows the whole surrounding map dimmed, with the selected layer/group drawn more prominently above the scenery. Only the selection's changes use red/green highlights; changes elsewhere remain neutral context. Fit still targets your selection, and both panes share pan/zoom.
- In **Changes**, with context enabled, unchanged navigator entries are grouped in a separate **Unchanged (count)** section after the changed entries. Click its header to expand or collapse it. It starts collapsed when there are differences and opens automatically for equal maps. Prev/Next always skip this section, even when expanded. Folding sections keeps your current inspection and scroll position, except for the necessary clamp when the remaining content is shorter. Each section retains its selection and sidebar scroll position; returning to a map selection restores its inspection camera.
- Red **minus** markers identify old content. Green **plus** markers identify new content. Replacements appear on both sides. Added/deleted layers and groups remain navigable, including empty ones. Textual statuses and exact fields accompany color.
- A layer resize, rename, other layer/group property edit or layer/group reorder does not tint unchanged tiles or objects. Those changes remain in the tree and inspector; Context reveals the unchanged content in its source colors. Red/green content highlights identify actual tile/object changes or wholly added/removed layers.
- Envelopes in both panes use time zero plus each object's persisted time offset. For full-map context, surrounding groups apply their source parallax to the current camera (the initial shared reference plus pan/fit translation). This keeps zero-parallax sky and low-parallax scenery visible when inspecting distant tiles. The selected owning group, including its unchanged siblings, uses an independent inspection translation so Fit and pan can reach even zero-parallax objects. Source offsets, envelope evaluation and game-space clipping remain observable. The viewer has its own camera and clipping; it does not switch the active editing tab or change the source animation evaluators.
- Missing resource content and invalid references are explicit issues. Selecting a resource includes references to affected layers. Sound source shapes and properties are inspected visually; comparison does not play sounds.

Comparison tabs retain the editor's File, Tools and Settings menus, toolbar area and status bar. New, Load, Help, Exit, Compare maps, Reopen comparison and Close comparison remain available. Map editing and saving commands remain visible but grey and inert, including through shortcuts and the action prompt. File dialogs keep their own keyboard input; Escape closes an open dialog before returning from the comparison. The shared tabs and menus render in front of map content, while hiding the normal editor GUI still provides a full map viewport.

The comparison sidebar uses the editor's native 100-unit minimum. All four section icons remain on one row at narrow widths, while the visibility footer uses two rows. Names and the Unchanged header stay clipped to their rows, and the layer eye/fold targets stay available. The editor owns one sidebar width, with the native 100-400-unit limits, shared by maps, selectors and comparisons. Switching, refreshing or reopening a comparison uses the latest width; camera, selection, visibility and scroll preferences remain independent for each comparison. **Back**, **Swap**, **By layer/group**, **Context**, **Prev**, **Next** and **Fit** share one 22-unit toolbar row with native 5-unit gaps. The comparison status bar uses its full width for the change summary or hovered control help; the normal editor's Envelopes, Server settings and History footer buttons are omitted. Normal map tabs retain their existing toolbar, mode icons and footer actions.

Selecting **Ordered server settings** automatically uses a full-height, shared-scroll Before/After text view. Unchanged text remains neutral; only inserted or removed substrings use the side's green or red color. For example, `sv_pauseable 1` versus `sv_pauseable 0` highlights only `1` and `0`. Multibyte characters stay whole, including when commands wrap, and changed line-number gutters also identify empty-command differences. Source line numbers are one-based and can differ across a row after an insertion. `[no line]` with a `-` line number marks an absent side; an empty command retains its real line number, and literal `(absent)` text remains a command. Text wraps without truncation. Click a changed row to select it; P/N reveal the corresponding aligned row, including distant changes. Settings are only displayed, never executed.

Selecting an **envelope** automatically shows paired plots with the same time and value axes, labeled color/position/sound channels, and shared channel toggles. Curves are sampled previews and may omit narrow features between samples; use the inspector for exact fields. Red/green markers emphasize changed points. Selecting a point field highlights that point in white on every visible channel, including points outside the overview marker set; it does not identify an individual channel or tangent. Hidden channels also hide their selected-point markers. A notice appears when no channels are visible. Click a changed marker to inspect its first changed field. The inspector retains exact fixed-point values, Bezier tangent fields and affected-layer references. Each curve stops at its own final point and uses the actual terminal value; shorter envelopes never repeat or extrapolate. Absent, empty, single-point and differing channel types are labeled explicitly. Plot value bounds include the used Bezier tangent values. Settings and envelope gestures preserve the map camera.

## Matching limits

Map files do not contain persistent identities for arbitrary groups, layers, quads, or sound sources. Matching first uses unique gameplay roles, then compatible identical content, then unique compatible names. Distinct names disambiguate identical-content buckets. Remaining equal-sized compatible ordered spans are aligned conservatively. A unique exact-content match is unambiguous even without a name. Duplicate-content matches retain **[?]** uncertainty. Ordered-span fallback is also marked **[?]**, and matching details explicitly call it a positional fallback. Unnamed rows start with their source index and show both indices when shifted. Name tooltips and Structure / matching details provide both zero-based Before/After indices. Equal indices alone do not establish historical identity. Cross-group moves can appear as deletion and addition.

Relative order is compared only among matched items. Inserting a layer or quad therefore does not mark every later item as modified. Resource references use canonical content fingerprints instead of table indices, so renumbering resources and preserving references does not change the visual result. Embedded bytes, external image references, relevant envelope channels and Bezier tangents are compared. Unused tangent/union fields, tile skip/opaque flags, padding, visibility, selection, brush, camera, filenames, and other editor-only state are excluded from content equality. Persisted automapper configuration, seed, and automatic mode are included; its runtime reference-layer selector is not a saved map property.

The snapshots own their comparison data. Tiles and changes are sparse and coordinate-based. Comparison runs on one globally shared, cancellable worker after const snapshots have been captured on the editor thread. Source revisions are validated before navigation, rendering, and publication; obsolete results are discarded. Cancelled work is reaped without blocking tab transitions. Capturing very large documents and copying embedded resources can briefly occupy the editor thread before cancellation is processed.

Settings alignment and inline text ranges run once on the comparison worker. Inline ranges preserve a common prefix and suffix on UTF-8 codepoint boundaries, then align the remaining codepoints within at most 65,536 cells per command and 1,048,576 cells across the whole result. Exhausting either budget conservatively highlights the unmatched middle. Linear trimming is proportional to input bytes and checks cancellation; inline alignment never runs during rendering, resizing or unchanged tab switches. Line alignment first preserves equal prefixes and suffixes, then uses a longest common subsequence within a budget of 1,048,576 table cells (4 MiB). Larger unmatched spans align by position and display a conservative-alignment notice; this can report extra replacements but never drops a command. Cancellation discards the whole result. Wrapped text heights are cached by column width and only visible aligned rows are rendered. While dragging the sidebar divider, settings retain their cached wrapping and stay clipped to each column; releasing the divider reflows the text once. Envelope plots cache at most 1,025 samples per channel and 512 overview markers per side; the selected point is shown separately on visible channels. Plot preparation and source-reference lookup run when selection changes, and resource-view caches are rebuilt when their owned snapshots change. Unchanged tab switches retain these caches.

Full-map context respects each source's layer order, group offsets, parallax and clipping. Sound handles and gameplay text appear only in the selection. Buffered graphics backends reuse tile geometry for the visible area plus a small panning margin; they do not upload the whole map. Off-screen tiles and quads are culled. Visible quads retain source order and envelope styling within one batch per layer/pass, with difference markers drawn afterward. Comparison buffers are released on close, snapshot replacement or actual source disposal. Older graphics backends use the same bounded tile traversal without GPU caching.

## Reproducible native-editor checks

Use a dedicated test profile and scratch tabs. Keep the bundled map files intact. For each fixture (`coverage.map`, `Tutorial.map`, `Tsunami.map`, and `Sunny Side Up.map`):

1. Open the fixture twice. Change only editor visibility, selection, camera, and animation state in the second tab. Launch from the first tab's active context into the second tab, then repeat through Tools. Both comparisons should report no content differences. Enable context and inspect the actual textures and layout.
2. In the second tab, paint and erase a tile without saving. Change a tele/tune number, switch number/delay, or speedup force/max-speed/angle while keeping its type unchanged. Compare again. Check old/new markers, exact coordinates and fields, direction, and Swap.
3. Insert a decorative layer before an existing layer, and insert a quad before existing quads. The inserted items should appear as additions; later unchanged items should remain unchanged. Swap two existing layers/quads to check relative draw-order reporting. Add/delete an empty group and resize a tile layer to check structural rows and coordinate alignment.
4. Change a group's offset, parallax, and clipping. Inspect both panes, then both navigation modes, linked pan/zoom, Fit, and window resizing. Check the selected source textures at multiple zoom levels and envelope time zero.
5. Replace an embedded image or sound, change an envelope point and a used Bezier tangent, edit map metadata, and insert duplicate server-setting commands. Check resource entries, affected-layer references, exact values, command positions, and order. Renumber equivalent resources with references preserved and check for false changes.
6. Before comparison, record dirty flags, history sizes, current layer/group/quad/envelope selections, brush, and both source camera states. While comparing, attempt painting, deletion, undo/redo, typing, save shortcuts, and brush shortcuts. Return through both Back and Escape, including while a mouse button is held. These attempts must leave source editing state and content unchanged, apart from independently scheduled autosave bookkeeping.
7. Close a source through an already pending save completion; also load/drop a map externally while comparison is open. Actual disposal must close dependent comparison tabs; an unrelated load/drop must preserve them and safely select the new map. Closing input must not reach the destination editor.
8. Record snapshot/comparison time, memory behavior, and navigation responsiveness on the largest fixture, including cancellation during comparison. Automated loading alone does not validate the viewer.

## Build and automated checks

Use a compiler environment appropriate for your platform. On Windows, use a Visual Studio Developer PowerShell and set `VSLANG=1033` **before the first CMake configure**, so Ninja records the matching English include-dependency prefix. Use a fresh build directory if the compiler language or cached dependency prefix has changed.

```sh
cmake -S . -B build/map-comparison -G Ninja -DCMAKE_BUILD_TYPE=Debug -DDOWNLOAD_GTEST=ON
cmake --build build/map-comparison --target game-client testrunner
build/map-comparison/testrunner --gtest_filter=MapDiff.*:MapCompareRender.*:Editor.*
```

Append `.exe` to executable names on Windows. Supply your platform's dependency options as usual.

For reproducible native verification, configure a separate build with `-DMAP_COMPARE_NATIVE_TEST=ON`. This replaces the editor factory only in that opt-in configuration; the normal client contains no test access or instrumentation. The test client requires a working desktop graphics session and OpenGL 3.3. It is unsuitable for a headless client build.

```sh
cmake -S . -B build/map-comparison-native -G Ninja -DCMAKE_BUILD_TYPE=Debug -DMAP_COMPARE_NATIVE_TEST=ON
cmake --build build/map-comparison-native --target run_map_compare_native
# Once built, the same suite is registered with CTest:
ctest --test-dir build/map-comparison-native -R '^MapCompare.Native$' --output-on-failure
```

The runner creates isolated storage below the build directory, retains per-run reports and screenshots, and fails on assertion failures, crashes, or timeout. The checked-in harness exercises the real editor and input/render lifecycle. It covers special tile arrays, angle-only speedup edits, ignored fields, semantic resource renumbering with actual presentation references, snapshot independence, a nonempty brush and source histories, held closing input, immediate reopen/cancel cleanup, changed-to-equal reopening, Home and navigator mode/context changes, wrapped inspector values, and distant zero-parallax content. A solid white source texture produces deterministic red/green tile-interior framebuffer samples; those pixels are asserted independently of screenshot writes. The bundled-map corpus also records isolated capture-of-both-sources and pure comparison timings.

The native suite also exercises a dense 2048-by-1024 tile layer, automatic fit, wheel limits, and rendering in all three context modes and both navigation modes. It checks that Fit reveals distant changes despite hidden unchanged layers or group clipping, samples changed tiles at the far edge, and bounds marker render submissions. A deterministic unit test bounds coordinate reads when culling a 20,000-column layer. To benchmark downloaded maps separately, set `DDNET_MAP_COMPARE_PERF_BEFORE` and `DDNET_MAP_COMPARE_PERF_AFTER` to their paths before running the native test. The runner copies them into isolated storage and makes in-memory layer and group property edits; unchanged content remains neutral when context is enabled. It logs frame timings including framebuffer synchronization; it does not impose hardware-specific timing assertions.

Full-context checks sample actual framebuffer colors across groups, verify neutral context and highlights above overlapping siblings, test clipping and nonzero parallax, and assert that steady frames reuse tile buffers without uploads. An asymmetric atlas checks tile indices and all flip/rotation combinations against the immediate fallback, including after cache rebuilds, zoom changes and travel through empty areas. The performance fixture also measures rapid pan/zoom through the map to include cache rebuilding costs.

Unchanged-content checks cover resize, layer/group properties and draw order, actual tile/quad/sound edits, and whole-layer additions/removals in all context and navigation modes. Set `DDNET_MAP_COMPARE_TINT=1` to run these checks alone. Combining it with the two local-map variables selects the targeted 1AndOnLyLife regression (Game width 999 to 955); it checks visible shared content and real change markers against the captured framebuffer without modifying the source maps.

Navigation checks use real toolbar and keyboard input to visit separated tile edits, a quad edit, group properties, and an added empty group's structure and properties. They cover both directions, wraparound, ambiguous unchanged siblings, child-property fitting, collapsing/expanding the unchanged section, arrow/End/Page Down movement across its header, and equal-map selection. Framebuffer samples distinguish selection-only context from full-map context in both layer and group modes.

Visibility checks use actual tree eye/fold buttons, sample hidden foreground/background layers in both framebuffers, verify parent/child choices and Show all, inspect added/removed layers, and compare source visibility flags before and after. A 60-layer fixture checks wheel-scrolled Unchanged expansion/collapse, preserved hidden selection/camera, independent sidebar scroll positions and navigation into folded groups. The local performance run also measures full-map context with the Layers tree open.

The textured-quad framebuffer checks also overlap red and blue quads to verify batch draw order and alpha.

The pure-core suite covers coordinate-preserving resize, all tile value fields, owned snapshots, layer/object insertion and order, duplicate names, semantic resource renumbering, missing content, metadata and ordered duplicate commands, group changes, envelope/source properties, cancellation, and sparse large extents. Native rendering and source-state checks must be recorded separately; passing this corpus does not establish that all real-world maps are issue-free.
